# As Quatro Perguntas de Engenharia

Sempre que eu encontrar um novo problema, antes de pensar na linguagem de programação, devo responder estas quatro perguntas.

---

## 1. O que eu preciso lembrar?

Tudo aquilo que precisa permanecer armazenado durante a execução do algoritmo.

Exemplos:

- Código da peça
- Quantidade
- Nome do cliente
- Resultado
- Operador
- Índice

Ferramenta utilizada:

Variáveis.

---

## 2. O que eu preciso repetir?

Toda ação que deverá acontecer diversas vezes.

Exemplos:

- Ler todas as linhas de um relatório.
- Percorrer todos os caracteres de uma expressão.
- Verificar todos os produtos.
- Contar todos os livros.

Ferramenta utilizada:

for

Pergunta que devo fazer:

"O que precisa acontecer várias vezes?"

---

## 3. Que perguntas preciso fazer?

Toda decisão nasce de uma pergunta.

Exemplos:

- Existe estoque?
- O pagamento foi confirmado?
- O caractere é um número?
- O operador é válido?
- O usuário possui autorização?

Ferramenta utilizada:

if

Pergunta que devo fazer:

"Qual regra da realidade precisa ser verdadeira?"

---

## 4. O que acontece quando a resposta for diferente?

Nem toda pergunta terá resposta positiva.

Quando a regra não for satisfeita, o algoritmo precisa saber qual caminho seguir.

Exemplos:

- Mostrar erro.
- Encerrar operação.
- Solicitar nova informação.
- Ignorar registro.
- Continuar procurando.

Ferramenta utilizada:

else

Pergunta que devo fazer:

"Se a regra não for satisfeita, qual deverá ser o próximo caminho?"

---

# Método Sirius

Antes de escrever qualquer código, responder:

1. O que preciso lembrar?
2. O que preciso repetir?
3. Que perguntas preciso fazer?
4. O que fazer quando a resposta for diferente?

Somente depois escolher a linguagem e escrever o algoritmo.

"A linguagem é apenas a forma de escrever uma solução. 
A solução nasce da compreensão do problema."
